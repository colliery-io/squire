# UI Theme Guidelines

Version: 1.0

Purpose:

This document defines how the Squire visual language is applied to the user interface.

This guide bridges:

* color-palette.md
* materials.md
* icon-guidelines.md
* illustration-guidelines.md

and establishes how screens, cards, navigation, rewards, and progression systems should appear.

---

# Design Philosophy

Squire is a productivity application presented as a fantasy adventure.

The application should feel:

* Familiar
* Readable
* Friendly
* Motivating

The application should not feel:

* Like a game console UI
* Like a fantasy MMORPG
* Like a collectible card game
* Like a complex RPG

Fantasy should enhance usability.

Fantasy should never replace usability.

---

# Core UX Principle

Use familiar mobile interaction patterns.

Apply fantasy through presentation.

Examples:

Good:

* Standard navigation bar
* Fantasy-themed icons
* Parchment cards
* Quest-themed language

Bad:

* Unusual navigation systems
* Hidden interactions
* Fantasy mechanics replacing common UX patterns

Users should immediately understand how to use the application.

---

# Shared Interface Philosophy

Squire ships as a single application.

Parents and children share the same visual language.

Benefits:

* Reduced maintenance
* Reduced visual drift
* Stronger product identity
* Easier onboarding

Differences between parent and child experiences should come from workflow and permissions.

Not from separate visual systems.

---

# Layout Hierarchy

Information should flow through a consistent hierarchy.

1. Purple Header
2. Content Area
3. Quest/Reward Cards
4. Progress Indicators
5. Navigation

The hierarchy should remain consistent throughout the application.

---

# Screen Structure

Preferred Structure:

Header

↓

Primary Content

↓

Secondary Content

↓

Navigation

Avoid:

* Overlapping panels
* Floating fantasy elements
* Excessive decorative clutter

---

# Card System

Cards are the primary information container.

Cards should use:

* Parchment surfaces
* Wood framing
* Rounded corners

Cards should feel:

* Physical
* Readable
* Friendly

Cards should not feel:

* Heavy
* Ornate
* Decorative for decoration's sake

---

# Quest Cards

Quest cards are the most important component in the application.

Visual Structure:

Header

↓

Quest Information

↓

Reward Information

↓

Action Area

Material Ownership:

Body:
Parchment

Frame:
Wood

Priority Indicators:
Purple / Orange

Reward Values:
Gold

Quest cards should feel like:

"A page from an adventure journal."

Not:

"A quest scroll from an MMORPG."

---

# Reward Cards

Reward cards represent tangible real-world rewards.

Examples:

* Movie night
* Ice cream trip
* Screen time
* Toy allowance
* Family outing

Reward cards should feel:

* Valuable
* Exciting
* Physical

Visual inspiration:

Treasure discovered after an adventure.

---

# Reward Presentation

Rewards should be displayed using treasure chest metaphors.

Examples:

* Reward Vault
* Treasure Chest
* Reward Collection

Avoid:

* Trophy halls
* Military displays
* Competitive ranking systems

The emotional goal is:

"Look at the treasures I've unlocked."

Not:

"Look at the trophies I've won."

---

# Progress Indicators

Progress should feel earned.

Preferred Style:

Fantasy-inspired progress bars.

Materials:

Wood
Gold

Progress bars should remain:

* Simple
* Readable
* Familiar

Avoid:

* Complex maps
* Winding paths
* Decorative trackers

Progress should always be easy to understand.

---

# Currency Display

Coins:

Represent progress.

Gems:

Represent achievement.

Currency displays should remain simple.

Avoid:

* Coin piles
* Gem hoards
* Excessive visual effects

Currency should feel meaningful.

Not overwhelming.

---

# Achievement Display

Achievements should feel collectible.

Examples:

* Badge collections
* Achievement books
* Treasure inventories

Achievements should celebrate accomplishment.

Without creating pressure or competition.

---

# Empty State Philosophy

Every empty state should communicate opportunity.

Never failure.

Examples:

No Active Quests:

"Your quest board awaits a new adventure."

No Rewards:

"A treasure chest waits to be filled."

No Streaks:

"A campfire waits to be lit."

The message should always be:

"Your next adventure begins here."

---

# Navigation

Use standard mobile navigation patterns.

Visual treatment:

* Fantasy-inspired icons
* Purple branding
* Clean layouts

Users should instantly understand navigation.

Do not reinvent common mobile conventions.

---

# Modal Windows

Dialogs should feel like notices from an adventure journal.

Materials:

Parchment

Optional:

Wood framing

Avoid:

* Heavy fantasy ornamentation
* Decorative clutter

Readability comes first.

---

# Forms

Forms should remain modern.

Examples:

* Quest creation
* Reward creation
* Parent settings

Fantasy theming should remain subtle.

Forms exist to complete tasks efficiently.

---

# Visual Density

Target:

Moderate

The application should feel rich.

Not busy.

Every decorative element must serve a purpose.

When in doubt:

Remove decoration.

---

# Accessibility

Readability always wins.

Fantasy styling must never reduce:

* Contrast
* Discoverability
* Usability
* Accessibility

If decoration conflicts with usability:

Usability wins.

---

# Final UI Test

Before approving a screen:

□ Feels like Squire

□ Uses standard mobile UX patterns

□ Supports readability

□ Uses approved materials

□ Uses approved colors

□ Reinforces quest and reward themes

□ Rewards feel tangible

□ Empty states feel encouraging

□ Navigation is immediately understandable

□ Fantasy enhances usability

If any answer is no, revise the design.
