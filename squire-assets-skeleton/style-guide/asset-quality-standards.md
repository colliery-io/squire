# Asset Quality Standards

Version: 1.0

Purpose:

This document defines the acceptance criteria for all Squire visual assets.

These standards apply to:

- Icons
- Illustrations
- Badges
- Textures
- Banners
- Decorative assets
- Future visual content

The purpose of this document is to ensure consistency, quality, and maintainability across the entire asset library.

All asset reviews should reference this document.

---

# Review Outcomes

Every asset review must result in one of three outcomes.

---

## Accepted

The asset meets all required standards.

The asset may be added to the approved library.

---

## Revision Required

The asset is generally correct but requires improvement.

The asset should be revised and reviewed again.

---

## Rejected

The asset violates one or more core standards.

The asset should not be used.

A new version should be generated.

---

# Core Principle

Every asset should strengthen the Squire identity.

If an asset could belong equally well to:

- an MMORPG
- a fantasy combat game
- a mobile gacha game

then it probably does not belong in Squire.

---

# Brand Alignment

## Acceptance Criteria

The asset should feel:

- Encouraging
- Friendly
- Positive
- Family-oriented
- Adventure-focused

The asset should reinforce:

- Growth
- Achievement
- Progress
- Exploration
- Community

---

## Rejection Criteria

The asset primarily communicates:

- Combat
- Fear
- Aggression
- Intimidation
- Competition

Reject.

# Readability Standards

Assets must remain recognizable at their intended display size.

---

## Icons

Required:

Recognizable at 64x64

Preferred:

Recognizable at 32x32

---

## Silhouette Test

Convert the icon to a black silhouette.

If the object remains recognizable:

Pass.

If recognition depends on internal details:

Fail.

---

# Composition Standards

The asset should communicate one idea.

Examples:

Good:

- Coin
- Gem
- Scroll
- Chest

Bad:

- Coin pile
- Complex scene
- Multiple unrelated objects

The primary subject should be immediately identifiable.

---

# Material Compliance

Materials must follow materials.md.

Examples:

Correct:

- Gold = progress
- Gem = achievement
- Purple = hierarchy
- Wood = structure
- Parchment = information

Incorrect:

- Gem used as common decoration
- Gold used as primary background
- Stone used for basic UI elements

---

# Color Compliance

Colors must follow color-palette.md.

Reject if:

- Colors violate rarity mappings
- New colors are introduced without justification
- Palette drift occurs

Examples:

Correct:

Purple = Rare

Orange = Epic

Incorrect:

Orange = Common

Purple = Progress Currency

---

# Detail Density

Target:

Medium Detail

The asset should contain:

70% Primary Forms

20% Secondary Forms

10% Small Details

---

## Reject If

The asset relies on:

- Tiny details
- Micro-textures
- Excessive ornamentation

to communicate meaning.

---

# Visual Clarity

The user should understand what the object is within seconds.

Ask:

"What is this?"

If the answer is uncertain:

Revise.

If the answer requires explanation:

Reject.

---

# Magic Effects

Fantasy is communicated through theme.

Not visual noise.

---

## Allowed

- Decorative engravings
- Heraldic details
- Fantasy craftsmanship

---

## Avoid

- Magical glow
- Floating particles
- Arcane energy
- Spell effects
- Excessive sparkles

---

## Reject If

The asset feels magical when it should feel physical.

Examples:

Bad Coin:
Glowing enchanted artifact

Good Coin:
Beautifully crafted currency

---

# Emotional Tone

Assets should evoke:

- Pride
- Excitement
- Curiosity
- Accomplishment

Reject assets that evoke:

- Fear
- Threat
- Anger
- Pressure

---

# Child-Friendly Review

Ask:

Would a 6-year-old understand this?

Would a 10-year-old enjoy this?

Would a parent feel comfortable with it?

If any answer is no:

Revise.

---

# Production Quality

Reject assets that contain:

- Blurry rendering
- Distorted anatomy
- Inconsistent lighting
- Visual artifacts
- Cropping mistakes
- Low-resolution details

---

# Consistency Review

Compare against approved assets.

Ask:

Does this belong in the same world?

If not:

Revise.

Consistency is more important than novelty.

---

# Icon-Specific Standards

Pass Requirements:

□ Single object

□ Transparent background

□ Recognizable at 64px

□ Upper-left lighting

□ Soft painted edges

□ Medium detail density

□ No unnecessary effects

□ Uses approved materials

□ Uses approved colors

---

# Illustration-Specific Standards

Pass Requirements:

□ Supports brand vision

□ Family-friendly

□ No combat themes

□ Positive emotional tone

□ Consistent rendering style

□ Matches approved environments

□ Reinforces adventure and growth

---

# UI Asset Standards

Pass Requirements:

□ Supports readability

□ Does not reduce usability

□ Uses approved hierarchy

□ Uses approved materials

□ Works on mobile screens

□ Supports accessibility requirements

---

technical-specifications.md

---

# The Final Question

Before approving any asset, ask:

"Does this make Squire feel more like Squire?"

If the answer is unclear:

Revise.

If the answer is no:

Reject.

If the answer is immediately yes:

Approve.
